# Agent-authored product delivery

Dispatch **Factory bootstrap** with `agent_products=true` as the repository
owner. Use a reviewed ref and keep `pages_drill=false`. The hosted workflow
uses the existing Copilot credential. It creates and evolves both example
products, signs the checked bundles and rehearses release and recovery inside
the hosted job. The production Trail Desk Pages workflow is a separate lane.

## Product contract

Each product has `initial` and `next` snapshots under
`examples/agent-products`. The same five files describe each snapshot.

| File | Review contract |
| --- | --- |
| `product-requirements.md` | Epic and feature outcomes, stories and CALM owners, acceptance criteria and check references |
| `execution.json` | Stable product ID, approved runtime and source paths, entry point and any reviewed migrations |
| `architecture.json` | Authoritative FINOS CALM model |
| `architecture.c4` | Canonical LikeC4 projection of the CALM model |
| `acceptance.json` | Independent case IDs, story links, JSON input and exact expected JSON output |

The runtime interface accepts one JSON value on standard input and emits one
JSON value on standard output. Node and Python use standard libraries and
immutable container images. Onboarding another product that meets this
contract requires its reviewed descriptors. The workflow discovers the
qualification matrix from those directories. Each product keeps the same
runtime across the two revisions. A new runtime requires a reviewed executable
adapter and image pin.

Trail Desk implements catalog and step-free filtering and evolves to support
distance ordering. Stock Ledger replays an inventory movement journal and
evolves to calculate reorder quantities. The repository contains their
contracts and architecture, with source generated by the hosted agent.
The Trail Desk example exercises the product's rules through a CLI interface.

## Authority and evidence

The Copilot worker uses separate bounded planner, coder, test analysis,
reviewer and repair calls in empty temporary workspaces. It can propose only
the approved source files. Copilot tools and built-in MCP servers are disabled,
and an emitted tool request fails the job. Agent review can block promotion.
A failed check or review permits at most one repair per revision. Case inputs
and expected outputs stay with the deterministic checker. A repair sees failed
case and story IDs. Agent audit artifacts retain session IDs, response digests,
plans, review findings, attempts and source digests. The independently checked
bundle binds the complete audit digest and the accepted source to the signature.

A separate verifier job has no Copilot credential. It checks CALM and LikeC4
with pinned native tools, recomputes impact and executes all reviewed cases for
both revisions. Candidate source executes in short-lived containers with no
network, read-only source, resource limits and no credential mounts. The host
owns comparisons. The test analysis agent advises the reviewer. It cannot
modify the held-out acceptance suite or declare a verification pass.

Only the signing job receives attestation write and OIDC permissions. A
separate release job verifies the signed bundle against the workflow, commit
and GitHub-hosted signer and tests rejection of changed bytes. It rehearses
creation, update, fault and re-observation for each product and preserves the
recovery report. The deployment exercise is isolated to the runner. Production
environment and Pages credentials are outside this workflow.

## Architecture changes

Planning supports CALM nodes and interfaces, connects, interacts, composed-of,
deployed-in and flows. It checks the canonical LikeC4 view, compares normalized
models, follows dependency impact and identifies affected stories and cases.
The independent verifier still runs the complete regression suite. Breaking
findings require an explicit `migrations` entry in `execution.json` with the reported `kind` and
`id` and an affected, acceptance-covered `story`. Use `node` to disambiguate
node-scoped findings. Unknown relationship semantics fail closed.

Generate a view with
`node --input-type=module -e 'import {readFileSync} from "node:fs"; import {renderLikeC4} from "./factory/architecture-plan.mjs"; process.stdout.write(renderLikeC4(JSON.parse(readFileSync(process.argv[1],"utf8"))))' PATH/architecture.json`.
Commit the resulting view alongside the changed CALM snapshot. The qualification
workflow checks both render consistency and native syntax.

The qualification uses two runtimes and one request/response contract. External
services, persistent databases, production rollout for the agent-authored
products, and agent-written integration tests as independent gates require
additional adapters and qualification.
