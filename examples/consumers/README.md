# Three independent blueprint consumers

These are **language-specific acceptance fixtures**, not three versions of the
factory. Each consumer uses the same APMX package and its own reviewed
`.forge/verify-change`. Candidate patches may modify `src/` only;
protected tests and checkers are copied from the approved base into a disposable
directory. No candidate code is run with repository credentials.

| Consumer | Toolchain | Independent check |
| --- | --- | --- |
| python-api | Python 3 | `python3 -m unittest discover -s tests` |
| go-service | Go | `GOWORK=off GOPROXY=off go test ./...` |
| typescript-web | TypeScript compiler + Node.js | `tsc -p tsconfig.json && node --test tests/*.test.cjs` |

These checks require the respective language tools to be installed by the
consumer. The factory does not install or select an application language.
Each consumer is a standalone seed with a reviewed request, protected tests
and source. To run the full factory, stage one consumer in a clean directory,
initialize a Git repository with a reviewed base commit, and invoke the pinned
APMX factory documented in `../../blueprint/README.md`. The verifier takes
the **unapplied** `changes.diff` generated by the APMX build contract.

The TypeScript example intentionally uses the system `tsc`; production
consumers should pin the compiler through their own lockfile or toolchain
image. These fixtures are not evidence of an actual agent-generated change
until APMX execution and independent replay are performed.
